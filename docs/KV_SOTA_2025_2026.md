# KV-cache state-of-the-art baseline matrix — 2025/2026

Status: research-input survey for the SKV programme, reviewed 2026-09-26.

This document is a baseline-selection aid. External paper claims are not KVLab
results and must be reproduced or fairly approximated before comparison.

## Why this matters

SLHAv2's current bottleneck is not simply raw compression ratio. The active
questions are:

- which keys/values matter to downstream quality;
- how precision should vary by layer/head/token/state;
- which KV can be avoided, merged, replayed or offloaded;
- how much controller/search overhead the policy adds;
- whether logical savings become physical latency/memory gains.

The following work families therefore become explicit comparison classes.

## Low-rank KV projection

### Palu — ICLR 2025

Palu compresses KV state through low-rank projection derived from projection
weights and integrates reconstruction/fusion into attention execution.

Reference:
https://openreview.net/pdf?id=LWMS4pk2vK

KVLab implication:
- compare SLHA/KVLab rank-reduction decisions against a serious low-rank
  baseline rather than PCA-only toy controls;
- separate K and V handling;
- account for reconstruction/fusion cost, not only latent bytes.

## Learned / vector-quantized KV

### CommVQ — ICML 2025

CommVQ uses additive vector quantization and designs the codebook to commute
with RoPE, reducing decode overhead while targeting very low-bit KV.

Reference:
https://proceedings.mlr.press/v267/li25du.html

KVLab implication:
- add codebook/VQ as a representation-family baseline;
- explicitly test positional/RoPE compatibility;
- compare equal-quality storage, not only equal nominal bits.

## Adaptive and mixed-precision quantization

### AQUA-KV — ICML 2025

AQUA-KV exploits dependencies between K/V and compresses information that is
not predicted by compact adapters.

Reference:
https://proceedings.mlr.press/v267/shutova25a.html

KVLab implication:
- add predict-then-code residual information as a candidate family;
- measure adapter/calibration overhead and model dependence;
- compare against SLHA residual-energy and learned projection paths.

### KVTuner — ICML 2025

KVTuner searches hardware-friendly layer-wise mixed-precision KV
configurations based on sensitivity.

Reference:
https://proceedings.mlr.press/v267/li25dd.html

KVLab implication:
- SKV-7 must include calibrated static layer-wise mixed precision;
- an online Elastic policy is not useful merely because it beats one uniform
  bit width; it must beat the best admissible static calibrated policy after
  controller overhead.

## Two-stage sparse KV

### RocketKV — 2025

RocketKV combines coarse-grained KV eviction with fine-grained top-k sparse
attention and reports end-to-end GPU measurements.

Reference:
https://arxiv.org/abs/2502.14051

KVLab implication:
- compare one-stage Boolean admission against two-stage routing;
- separate coarse eviction from fine ranking;
- report quality, bytes fetched and end-to-end time together.

## Query-agnostic reusable importance

### KVzip — 2025

KVzip estimates KV importance through context reconstruction so one compressed
cache can be reused across later queries.

Reference:
https://arxiv.org/abs/2505.23416

KVLab implication:
- SKV-6 must explicitly compare query-aware and query-agnostic importance;
- reusable importance must be tested across multiple future queries;
- reconstruction quality is a candidate signal, not automatically downstream
  attention quality.

## Dynamic merging / importance allocation

### ZeroMerge — 2025

ZeroMerge combines token-importance allocation with residual merging rather
than treating eviction as pure deletion.

Reference:
https://arxiv.org/abs/2503.10714

KVLab implication:
- add merge/compensate as an alternative to keep/drop;
- account for merge metadata and update cost;
- compare against SLHA residual correction rather than assuming independent
  novelty.

## Heterogeneous / tiered KV

### HCAttention — 2025

HCAttention combines key quantization, value offloading and dynamic eviction in
a heterogeneous CPU/GPU attention path.

Reference:
https://arxiv.org/abs/2507.19823

KVLab implication:
- evaluate K and V separately;
- make CPU/GPU cooperation a first-class baseline;
- distinguish host/device transfer, offload latency and resident memory.

### LaCache — ICML 2025

LaCache uses a ladder-shaped pattern across token age/layers and iterative
compaction of older cache state.

Reference:
https://proceedings.mlr.press/v267/shi25b.html

KVLab implication:
- include multi-level age/layer compaction, not only three fixed HOT/WARM/COLD
  states;
- test static ladder policies before claiming an Elastic controller advantage.

## Mandatory baseline families derived from this survey

Where compatible with the declared experiment, SKV work should consider:

1. dense numerical KV;
2. current paged numerical KV;
3. current SLHA representation;
4. low-rank projection baseline;
5. static layer-wise mixed precision;
6. codebook/VQ representation;
7. one-stage Boolean/signature routing;
8. two-stage coarse + fine sparse routing;
9. query-agnostic reusable importance;
10. merge/compensate;
11. CPU/GPU heterogeneous tiering;
12. age/layer compaction ladder.

Not every experiment must implement all twelve. Every preregistration must
state which are applicable, which are unavailable, and why.

## Memorithm-specific opportunity

The ecosystem can test combinations that isolated papers usually treat
separately:

```text
KVLab evidence
  -> Boolean / ranking / mass selection
  -> SLHAv2 compressed representation
  -> FLAT numerical survivors
  -> ElasticXxx representation + placement control
  -> NNIS native Thor measurement
```

The scientific opportunity is not to concatenate mechanisms blindly. It is to
run factorial/ablation designs that identify which interactions survive matched
controls and real-model quality gates.
