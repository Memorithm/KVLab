# Full-cache oracle integrity

## Scope

`kvlab.oracle` freezes caller-provided K/V bytes and declared metadata. It is a backend-neutral byte oracle, not a model loader or device restore implementation. This correction keeps schema v1 and the digest algorithm unchanged for valid existing snapshots.

## Reproduced defects

The previous `FullCacheSnapshot.replay()` hashed a constant v1 header but did not check the snapshot's `schema_version` field. Replacing that field with 999 still yielded records. The replay generator also hashed `self.records` and then yielded from the original container: a caller-supplied list could be modified between generator iterations, exposing bytes that were never verified by the digest. A frozen dataclass does not freeze nested lists; shape lists also remained aliased after capture.

## Corrected behavior

Capture freezes record sequences and shape metadata before validating and hashing. K/V payloads remain immutable `bytes`; they are not transcoded or copied into a new numerical representation.

Replay requires an actual integer schema version 1, validates header types, captures an independent immutable tuple of layer records and shapes, checks its digest, and yields exactly that tuple. All verification occurs before the first yield. Mutating a caller-owned list after that point cannot substitute an unchecked record during an already validated replay. Starting a new replay against altered input still fails on the digest.

Layer IDs, dimensions and sequence lengths require actual integers rather than booleans or fractional values. Layer ordering and uniqueness are checked at both capture and replay. Model/tokenizer identifiers require non-empty strings and are not silently normalized.

## Compatibility and limits

Valid v1 record bytes, identity strings, ordering, logical byte totals and SHA-256 digests are unchanged. The regression fixture generated by the previous implementation retains digest `f1e6794bed8027b20c9779ed66508aca98da3325047a620f0b799a26c7b2fd73`.

The module intentionally does not infer dtype width or require opaque payload lengths to match declared tensor shapes. Those semantics remain the responsibility of the producing backend/codec. This code is not a sandbox against hostile Python code that bypasses frozen dataclasses, nor does it grant access to final evaluation splits.

## Tests

Eight new integrity tests complement the four unchanged oracle tests. They cover schema rejection, immutable nested capture, mutation between replay iterations, exact v1 compatibility, invalid types and explicit opaque dtype semantics.

Run:

```sh
python3 -m unittest discover -s tests -p 'test_oracle*.py' -v
```

## Relationship to physical replay

FLAT-ATTENTION PR #237 implements an independently allocated resident K/V prefix fork. Its copying and GPU-ordering guarantees are separate from this Python byte oracle. KVLab must not treat a physical per-layer copy, a logical checkpoint, an oracle digest and a complete model execution snapshot as interchangeable. This patch protects the existing evidence/replay path without introducing a dependency on an unmerged FLAT branch or claiming a GPU adapter integration.
